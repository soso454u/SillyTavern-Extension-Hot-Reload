# SillyTavern Extension Hot Reload

一个用于 SillyTavern 第三方 UI 扩展的智能更新与删除助手。它接管扩展管理器里的更新和删除按钮：能安全卸载的代码直接生效，无法安全卸载的脚本则自动执行一次保留现场的无感重启。

> 重点：浏览器没有通用的 ES Module 卸载 API。插件优先信任扩展自带的 cleanup hook；对无 hook 的常规扩展，Runtime Supervisor 只有在完整记录到可逆资源、且源码审计没有发现不可恢复操作时才会托管热载入；其他情况继续无感重启。

## 功能

- 继续使用 SillyTavern 官方 `/api/extensions/update` 接口拉取 Git 更新；
- 首次安装完成后通过官方 `install` 生命周期立即挂载，无需手动刷新页面；
- 兼容没有导出 `getExtensionManifest` 的 SillyTavern 版本，避免入口解析失败后整个设置面板消失；
- 直接接管扩展列表里原有的单个更新按钮；
- 接管原生“Update all / 更新全部”，避免 TauriTavern 在更新失败时仍按原生逻辑刷新页面；
- 接管原有的删除按钮，保留确认与可选数据清理，并尽量直接卸载当前运行实例；
- 在扩展管理器中加入“智能热更新全部”；
- 优先使用官方扩展工具栏，并能在旧版或魔改 DOM 中自动定位 Update All 所在的操作栏；
- 通过带版本参数的新 `<link>` 无闪烁替换 CSS；
- 对提供 `hot_reload`、`unload` 或 `disable` 钩子的扩展，先清理旧运行时，再导入新入口并调用 `update` / `activate`；
- Runtime Supervisor 从扩展启动阶段记录 SillyTavern 事件、DOM/jQuery 监听器、计时器、animation frame、Observer、未完成的 fetch、Worker/Socket 和明确归属的 DOM 节点；
- 无 cleanup hook 的扩展在追踪完整、账本非空且无风险特征时，可自动回收旧运行时并直接换新；
- 对已禁用的扩展只更新文件，不会意外启用其脚本或样式；
- 对不支持热卸载的普通扩展自动无感重启，一次应用全部更新；
- 删除时复用 Runtime Supervisor 的可逆资源账本；没有 manifest cleanup hook、但运行时已被完整托管的扩展也能直接热删除；
- 自动识别入口中的本地 ES Module 子模块，避免“入口是新版、子模块仍是旧缓存”的假成功；
- 识别 manifest 运行结构变化和 Worker 等本地运行资源，必要时保守地转入无感重启；
- Git 更新后只清除目标扩展自己的 Cache Storage 资源，不影响聊天、设置或其他扩展；
- Git 成功且新版 manifest 已验证后，若任何热卸载或新运行时步骤失败，自动降级无感重启，不把页面留在半卸载状态；
- 重启前保存未发送文本、光标选区、聊天可见消息锚点、页面及扩展面板滚动位置和已展开的设置区；
- TauriTavern 中不再重复等待已经发生的 `APP_READY`；使用一次性同源导航令牌强制载入新文档，恢复后自动清理地址；
- 可按标题恢复没有稳定 `id` 的扩展抽屉，并等待晚挂载面板出现后再恢复；
- 如果正在生成消息，会等生成完成或停止后再重启，不中断本次生成；
- 提供可选的“实验性强制热载入”，用于没有清理钩子的单文件/打包扩展；
- 单个扩展的 Git 请求失败、接口回包不完整或新版 manifest 无法验证时不会触发整页刷新，也不会影响批量队列中的其他扩展。
- Git 请求和资源检查都有超时保护，重启前预热最多等待 1.25 秒。

## 安装

1. 打开 SillyTavern。
2. 进入“扩展” → “安装扩展”。
3. 粘贴本仓库的 Git URL。
4. 安装完成后，在扩展设置里展开“扩展热更新”。

设置面板右下角会显示当前插件版本，便于确认浏览器实际载入的新版本。

仓库发布后可直接使用：

```text
https://github.com/soso454u/SillyTavern-Extension-Hot-Reload
```

## 使用

打开“管理扩展”，等待 SillyTavern 完成更新检查：

- 点击某个扩展右侧原有的下载图标：插件会自动执行智能热更新；
- 点击垃圾桶图标：确认后删除扩展；支持运行时卸载钩子的扩展无需刷新，不支持的扩展自动无感重启；
- 点击工具栏中的火焰按钮“智能热更新全部”：顺序更新当前检测到的全部可用更新；
- 如果提示“已更新并热载入”，当前页面已经使用新代码；
- 如果目标脚本没有清理钩子，Supervisor 会先判断能否托管换新；不满足安全条件时才出现“正在无感重启”遮罩，并在页面回来后恢复现场。

SillyTavern 原生的“Update all / 更新全部”也会被本插件接管，与火焰按钮使用同一条安全批量更新流程；只有至少一个扩展确认更新成功且确实需要重载运行环境时，才会无感重启一次。

### TauriTavern 安装排查

TauriTavern 按 Git 仓库名创建扩展目录，本插件的文件夹固定为 `SillyTavern-Extension-Hot-Reload`。如果安装器提示“已存在/已安装”，请分别检查“仅当前用户”和“全局”两处第三方扩展目录；截图所在目录中没有这个文件夹时，通常表示它装在另一作用域，或应用仍保留着旧的扩展发现结果。完全退出并重新打开 TauriTavern 后再确认，删除时只删除同名文件夹，不要删除其他扩展。

TauriTavern v2.2.0 的原生 Git 后端会先在临时目录完整拉取并校验 `manifest.json`，成功后才改名为上述正式目录。因此安装失败且正式目录不存在时，不应随便删除截图里的其他文件夹；需要保留安装弹窗或控制台给出的具体错误，才能区分网络、Git 引用、目录冲突或 manifest 校验失败。

## 更新安全层级

### 安全模式（默认）

只有 manifest 运行结构未变化，且满足下列条件之一时，才会在当前页面重新导入 JavaScript：

- 扩展 manifest 声明了可调用的 `hot_reload` 或 `unload` 钩子；
- 扩展声明了官方 `disable` 钩子，插件可用它停止旧运行时。
- 扩展没有 cleanup hook，但 Runtime Supervisor 从页面启动开始已完整跟踪它的可逆资源，而且新旧入口均通过保守审计。

如果入口文件还引用扩展目录内的其他模块，即使具备清理钩子，也会改走无感重启，除非扩展明确声明它会自行为所有本地模块和运行资源换新 URL。

这是日常使用推荐的设置。

### Runtime Supervisor（默认开启）

Supervisor 使用调用栈和回调上下文识别资源归属，只记录能够执行明确反操作的资源。它不 patch `Promise.prototype`，也不会尝试猜测如何回滚全局函数、Prototype、共享单例、已有 DOM 属性或外部注册表。

以下条件任一不满足时，会自动放弃托管热载入：

- Supervisor 启动前已有其他第三方扩展运行；
- 没有记录到可证明归属的活动资源；
- 追踪 API 安装失败或资源账本标记了不透明操作；
- 源码中出现全局赋值、Prototype 修改、既有 DOM 修改、动态代码、不透明动态导入或特殊媒体运行时等风险特征；
- 清理账本时有任何一项失败。

1.4.0 升级到 1.5.0 时，`loading_order` 的结构变化会先执行一次无感重启；重启后 Supervisor 才能从其他扩展加载前开始完整追踪。

### 通用无感重启（默认开启）

对于既没有清理钩子、又无法通过 Supervisor 安全托管的扩展，安全模式不会冒险把新旧脚本叠加，而是：

1. 完成所有 Git 更新和可安全替换的 CSS；
2. 保存输入框草稿、选区、聊天滚动锚点，以及扩展设置的展开和滚动位置；
3. 如果正在生成，等待生成正常结束；
4. 自动刷新一次浏览器运行环境；
5. 在 SillyTavern 发出 `APP_READY` 后恢复主要现场，并继续等待最多 6 秒来恢复晚挂载的扩展面板。

更新器会提前预热新版入口资源并尽快进入重启。这个过程内部仍然会刷新一次 JavaScript 运行环境——这是让任意、未适配扩展可靠加载新代码的唯一通用方式——但不需要用户手动刷新、重新寻找聊天或重新输入内容。可在扩展设置中关闭“不兼容脚本自动无感重启”，恢复为只提示稍后刷新。

### 实验性强制热载入

即使扩展没有清理钩子，也会导入带缓存破坏参数的新入口文件。旧模块本身仍留在内存中；如果它注册过未清理的事件、定时器、观察器或全局对象，可能出现重复执行。遇到异常时刷新一次页面即可恢复干净状态。

## 能与不能热更新的内容

| 内容 | 默认行为 |
|---|---|
| CSS | 安全换新并立即生效 |
| 已禁用扩展 | 只更新磁盘文件，不加载运行时 |
| 带清理钩子的 JS | 清理旧实例，导入新入口并重新激活 |
| 无清理钩子的常规 JS | 账本完整且风险审计通过时自动托管换新；否则无感重启 |
| 删除第三方扩展 | 有运行时卸载钩子时直接移除；否则自动无感重启 |
| HTML 模板 / 本地化 | 取决于目标扩展是否会在激活时重新渲染 |
| 多文件 ES Module / Worker 等本地运行资源 | 默认无感重启；明确声明自管版本 URL 时可直接热载入 |
| manifest 运行结构变化 | 自动无感重启，让 SillyTavern 重建官方生命周期状态 |
| SillyTavern 服务端插件 | 不在本插件范围内，通常需要重启服务端 |

## 给扩展作者

只需提供一个幂等的激活函数和一个彻底的卸载函数，即可进入最可靠的安全热更新路径。完整协议、示例和检查清单见 [HOT_RELOAD_PROTOCOL.md](HOT_RELOAD_PROTOCOL.md)。

最小 manifest 示例：

```json
{
  "js": "index.js",
  "hooks": {
    "activate": "onActivate",
    "update": "onUpdate",
    "hot_reload": "onHotUnload"
  }
}
```

## 安全说明

- 不使用 `eval`、远程脚本或第三方更新服务器；
- 只请求当前 SillyTavern 实例的同源扩展文件；
- Git 拉取、权限检查和路径清理由 SillyTavern 服务端完成；
- `clean` 钩子永远不会被热更新流程调用，避免误删扩展数据；
- 生命周期钩子设有 5 秒超时。
- Runtime Supervisor 不修改 `Promise.prototype`，不将“账本为空”当成无状态证明，也不会绕过本地模块缓存保护。

第三方扩展本身拥有与 SillyTavern 页面相同的权限。请只安装你信任的仓库。可参考 SillyTavern 官方的 [扩展使用说明](https://docs.sillytavern.app/extensions/) 与 [UI 扩展开发文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)。
